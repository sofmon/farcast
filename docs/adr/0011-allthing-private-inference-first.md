# ADR 0011 — AllThing: Private Inference First, External Providers by Declared Policy

**Status:** Proposed (2026-09-04). Nothing below is implemented. Every cloud figure is a model of a published rate card, dated and sourced, and none has been reconciled against an invoice — the standing the existing rate card has ([ADR 0009](0009-technocore-kernel-and-cost-metering.md) decision 10). Items marked *[to confirm live]* carry the procedure that confirms them; the first runbook of Phase 6 walks them.

**Date:** 2026-09-04

**Relates to:** Unblocks Phase 6 of [`PLAN.md`](../../PLAN.md), whose 6.1 ("Provider interface (Gemini, Claude, OpenAI)… Model selection and fallback") this ADR replaces. Constrained by [ADR 0003](0003-gke-autopilot.md) (what Autopilot admits and bills), [ADR 0005](0005-fatline-data-plane-ingress.md) (deny-by-default egress; the carrier is public, the authentication is not), [ADR 0007](0007-instance-owned-image-registry.md) (the instance's registry; digest pinning; third-party bases as untrusted transport), [ADR 0008](0008-in-cluster-key-delivery.md) (what may never rest in the cloud; "protected by Google not looking"; the frozen-contract discipline of decision 7), [ADR 0009](0009-technocore-kernel-and-cost-metering.md) (one limit, two figures, the kernel writes only zeros) and [ADR 0010](0010-application-image-builds.md) (the instance is the anchor; an instance-level egress allowance; a digest-pinned third-party image). **Amends** ADR 0009 decision 6 (a fourth tier value), the wording of ADR 0009 decisions 2 and 3 (a second kernel-written ConfigMap), and the billing premise of ADR 0003 §1 and `technocore/pricing` for accelerator Pods (they are billed by node shape, not by request). **Implements** ADR 0010 decision 5's instance-level egress allowance for the first time. Serves both pillars of [AGENTS.md](../../AGENTS.md), and corrects the sentences that describe AllThing as an abstraction over external AI services (*Consequences*).

---

## Context

The operator's brief, recorded verbatim because it decides what follows:

> *"Private inference should be a first-class capability, while external AI should remain optionally available under explicit policy."* — and — *"Where the repository contradicts assumptions in the prompt, the repository wins."*

AllThing today is a seven-line README ("cloud-agnostic layer over managed AI services (Gemini, Claude, OpenAI)"), an empty `main`, two `.gitkeep` directories, and one SDK interface — `sdk/go/ai.go`'s `AIAPI{Chat, ChatStream}` with `ChatRequest{Model, Messages}` — whose doc comment calls its shapes "a starting point, refined in the AI implementation phase". `farcast chat` is a phase-6.2 stub. Every sentence in the repository that mentions AllThing describes a shim over three vendors. So there is nothing to refactor, and the first question is not how to add a private backend to a provider abstraction but what the abstraction should have been.

Four things the brief assumed are not what the repository has, and each shapes a decision below:

1. **Planck has no runtime.** It provisions a cluster once and renders YAML; the only in-cluster actor that changes replica counts is TechnoCore, which writes `replicas: 0` and nothing else (`technocore/kernel/shutdown.go`, `technocore/README.md` "Everything the kernel writes is a zero"). Scale-to-zero inference needs an owner for the *up* direction, and the kernel is deliberately not it.
2. **The cost pillar cannot see a GPU, and the billing model is different in kind.** `technocore/pricing` knows vCPU-hour and GiB-hour; `kube.ResourceList` decodes `cpu` and `memory` and silently drops `nvidia.com/gpu`. Autopilot bills an accelerator Pod for the *whole node shape* that fits it (Google's own example: a Pod asking for 11 vCPU/40 GB is billed as a g2-standard-12), plus a premium, and enforces no minimum requests for it. A GPU line cannot be appended to `PodHourlyUSD(cpu, mem)`; the price is that of the node shape the Pod's requests fit, walked from a per-class ladder. This is ADR 0009 revisit trigger 1 — "a billed quantity the meter does not know about … a new mechanism, not a new constant" — arriving before the first accelerator Pod exists.
3. **Nothing can attribute an egress caller.** FatLine's proxy calls `Allowed(host)` on the default tenant; the deployed allowlist is empty; `farcast-system` carries no NetworkPolicy; and the rendered `fatline` Service publishes only the tunnel port, so the translator's `FARCAST_FATLINE_PROXY` URL is unroutable as rendered. "AI provider traffic must be declared" (PLAN 6.2) is agreed and has no mechanism.
4. **There is one limit, not budget tiers, and there are declarations, not modes.** FarCast has a mandatory instance limit with 50/75/90 % warnings and a warn-only projection, and it declares outbound access with a `reason` and denies the rest. An AI budget and a `mode:` switch would both be foreign objects.

Two ideas in the brief would damage the architecture and are replaced: a third "private-preferred" request class (it makes the privacy outcome a function of a cold start the application cannot see, and it *is* the fallback chain the brief asks to make impossible), and TechnoCore scaling inference up on request (the property that makes the cost enforcer trustworthy is that it never starts anything).

### The decision space

**Abstraction.**
- **A1 — a `Provider` interface with vLLM as one more provider.** "Provider" already means a cloud adapter opened by name (`planck.Open("gke")`, DataSphere's `gcs`); a second meaning inside `allthing` makes the word carry two ownerships, and it encodes the assumption being removed — that somebody else provides. A flat provider list is also the shape in which a private request lands on the wrong entry by a slice mistake. Rejected.
- **A2 — `Backend` (somewhere a request can be answered; its privacy is a property fixed at construction) plus `Runtime` (the lifecycle of a backend the instance owns, discovered by type assertion like `planck.RegistryProvider`), a pure `Policy` function and a `Router` that never widens its candidate set.** Grounded in the two backends that actually exist: an OpenAI-compatible HTTP+SSE server the instance starts and stops, and external HTTPS APIs with three wire dialects. The OpenAI dialect serves both the private runtime and `api.openai.com`, which is why privacy belongs to the backend and not to the dialect. **Chosen.**
- **A3 — a `database/sql`-style registry, a capability bitmask, an `Embedder` declared now "to fix the pattern".** Planck's registry exists for an open set of clouds; three compiled-in adapters chosen by a rendered flag are a `switch`. No concrete requirement asks for the rest. Rejected.

**Privacy classes.**
- **P1 — three: private-only, private-preferred, external-allowed.** Rejected, above.
- **P2 — two, on the request: `Private` (the zero value) and `ExternalAllowed`; preference among *permitted* places is the operator's policy, never the application's class.** **Chosen.**

**Scale-to-zero ownership.**
- **E1 — TechnoCore scales up on request.** Rejected: a kernel that also starts expensive things has no one left to stop it; demand is intelligence semantics, not money.
- **E2 — an HPA, KEDA or Knative.** Rejected: a controller that cannot read the kernel's level flaps against it; CRDs and a vendored controller are ADR 0009 revisit trigger 3's "take T3, not T1".
- **E3 — a separate controller Deployment.** Rejected: a standing Pod and a demand channel for a two-verb grant.
- **E4 — the AllThing gateway process scales its own inference Deployment through `technocore/kube` under a namespace Role pinned by `resourceNames`, and TechnoCore keeps stop-only authority.** **Chosen.**

**Tier of the inference Deployment.**
- **T1 — `app`.** Rejected: `app` carries the contract "restore is an operator act", and the kernel would report the instance's own GPU as an operator application in every report and in `RateByTier`.
- **T2 — `system`.** Rejected: the most expensive workload on the instance immune to the cost pillar.
- **T3 — a fourth value, `elective`: stoppable, stopped before any application, restarted only by its owner and only when the kernel's status permits.** **Chosen.** ADR 0009 decision 6 is amended accordingly.

**Where weights rest.**
- **W1 — downloaded and pushed from the operator's laptop.** Rejected: 10–30 GB through a laptop on every model change contradicts "the instance is the anchor, not one laptop" (ADR 0010) and inverts the lesser-device tiering.
- **W2 — fetched from the model hub at every cold start.** Rejected: every wake becomes a third-party fetch that the hub sees ("someone asked something private"), the inference Pod needs an egress rule, and a hub outage is an inference outage.
- **W3 — DataSphere.** Rejected: weights are public bytes with public hashes; the seal exists for data whose exposure is the harm. Coupling inference to `restart-sealed` makes private chat unavailable after every keyholder restart, pushes tens of GB through a data path shaped for MiB objects, and encrypts against a provider that holds the same bytes decrypted in GPU memory anyway. Integrity, the real need, comes from pinned hashes.
- **W4 — an OCI artifact in the instance registry, built by an in-instance Job.** The sovereign end state (the registry is the instance's artifact store, regional, torn down with the instance). Deferred: it needs a streaming, chunked OCI push and a Workload Identity push grant that ADR 0010 decided and nobody implemented. Named as a revisit trigger.
- **W5 — an instance-owned bucket read by a model streamer.** Rejected for now: a cloud-specific loader and a second IAM grant inside the runtime Pod for a benefit a disk already gives at this size.
- **W6 — a PersistentVolumeClaim filled once by an in-instance fetch Job running FarCast's own binary, through FatLine under an allowance that exists only while the Job runs, with every file re-verified by FarCast's own binary before every start.** Cloud-neutral Kubernetes, no hub on the wake path, no laptop transit, no new grant. **Chosen.** Its zonal pinning is stated in *Consequences*.

**The inference image.**
- **I1 — mirror it into the instance registry before the first milestone.** Rejected as a precondition: the CLI's OCI client buffers blobs in memory with a 512 MiB cap and refuses Docker Hub's cross-host bearer realm; a streaming client with an argued realm exception is real work with its own security review, and it buys no cold-start time today because Autopilot image streaming covers public Docker Hub as well as Artifact Registry.
- **I2 — a digest-pinned upstream reference recorded as a reviewed constant with its maintenance status (ADR 0010 decision 10's shape), stated plainly as node-level egress FatLine does not see; the mirror becomes mandatory when private nodes land.** **Chosen.**

**Attribution at FatLine for the provider allowance.**
- **F1 — provider hosts in the default tenant.** Rejected outright: the proxy has no caller attribution, so every application Pod would reach the provider host — the exfiltration path this ADR exists to close.
- **F2 — an mTLS egress listener whose tenant is the client leaf's URI SAN.** The correct 4.4 end state (the same seam applications will use with per-app leaves); it costs a TLS-terminating listener and a client leaf in the milestone for a property the network already gives. Recorded as the revisit.
- **F3 — a second plain egress listener on `:3129` whose decisions use a `system` tenant fixed by the socket, reachable only from AllThing's Pods by FatLine's own NetworkPolicy, populated by a rendered `--system-allow host=reason`.** Implements ADR 0010 decision 5 through the existing `Allow(tenant, host)` seam with the tenant derived from the socket, not from bytes. **Chosen.**

**Provider credentials.**
- **K1 — `metadata.yaml`.** Rejected: the non-secret record an operator backs up, diffs and may hand to a lesser device.
- **K2 — DataSphere.** Rejected: a provider key is not a crown jewel; sealing it makes external chat unavailable after every keyholder restart for no privacy gain.
- **K3 — a Kubernetes Secret rendered from stdin, consumed as environment.** ADR 0010 decision 4's "FatLine-server-leaf case, not the keyring case". **Chosen**; it moves behind `farcast.Secrets()` at 5.3 without changing the contract.

**External token spend.**
- **S1 — a per-provider cap or allowance enforced by AllThing.** Rejected: a per-subsystem budget the repository says does not exist.
- **S2 — reported as "what the meter cannot see" first; then accrued as `expected` through a named ConfigMap the kernel reads, never loosening the guard; external refused at `reached`.** **Chosen.**

**Cold start.**
- **C1 — the gateway holds the connection until ready.** Rejected: a cold start is minutes; a held connection under a 30-second client timeout is a guaranteed failure that also looks like an outage.
- **C2 — fail fast with a distinct sentinel; the request itself is the wake signal; the status endpoint explains; an optional wait derived from the caller's own deadline is additive, later.** **Chosen.**

### What Autopilot actually admits and bills — checked, not recalled

Fetched 2026-09-03 from Google's documentation and pricing pages (sources below); each is a fact this ADR leans on rather than a recollection:

- A GPU Pod is requested with `nodeSelector cloud.google.com/gke-accelerator: nvidia-l4` and `resources.limits nvidia.com/gpu: 1`; driver installation is automatic; on GKE ≥ 1.29.4 the Accelerator compute class is applied without a selector. Root is permitted; `hostIPC`, `hostPID`, `hostNetwork` and privileged are blocked; an `emptyDir` with `medium: Memory` is an allowed volume type (Google's own vLLM tutorial mounts one at `/dev/shm`); **image volumes are not** in the admitted set; accelerator Pods have no minimum CPU/memory request and may request ephemeral storage far above the 10 GiB general-purpose cap.
- Billing is by node shape: g2-standard-4 (4 vCPU, 16 GB, 1×L4) on demand is $0.7068/h hardware plus $0.0846/h Autopilot premiums (L4 $0.067 + 4×$0.003 + 16×$0.00035) ≈ **$0.79/h**, ≈ $0.81/h with a 100 GiB boot disk; Spot ≈ $0.46/h at today's live ~40 % discount (the pricing page promises 60–91 %; budget on the live number). 730 h ≈ $589/month; 1 h/day ≈ $24/month. Against a $100 limit, the modelled ~$73 floor and a ~$3.70 gateway leave ≈ $23 ≈ 28 GPU-hours a month; **below roughly $80/month private inference does not fit**, and the enable gate must say so. Every figure is modelled and unreconciled, and holds only under four conditions the runbook checks: Autopilot places the Pod on g2-standard-4 (the shape-choice rule is unpublished — Google's own example bills a Pod asking for 11 vCPU/40 GB as a g2-standard-12 at $1.12/h — so the runbook reads the node's `node.kubernetes.io/instance-type` label after the Pod schedules and the G2 line on the bill); the boot disk Autopilot provisions is about 100 GiB (an assumption; ~$0.015/h per 100 GiB); the cluster runs GKE ≥ 1.29.4-gke.1427000 (Planck leaves the version to the provider default); the region is us-central1 and the Spot quote is re-read on the day. The repository's standing premise that "Autopilot bills a Pod's requests" (`technocore/pricing`, ADR 0003, the TechnoCore README) is narrowed to general-purpose Pods, not declared false, and ADR 0003's "Spot ~50–70 % off" gains a dated footnote.
- A Pod is billed while `ContainerCreating` or `Running`; a Pod Pending for quota or stock-out has no node and costs nothing; an empty GPU node is removed automatically (the `optimize-utilization` profile) but the delay is unpublished, so hardware may bill for some minutes after the Pod terminates.
- `GPUS_ALL_REGIONS` defaults to 0 for new projects and the regional L4 quota starts at 0 or 1; quota is requested before the first Pod can schedule, and first-time increases have taken up to a week. L4 exists in `us-central1-a/b/c/f`.
- Google's image-streaming page lists public Docker Hub beside Artifact Registry standard and remote repositories as eligible sources, so a digest-pinned `docker.io` reference is expected to stream; whether it is at parity with a same-region Artifact Registry mirror is unmeasured — the page warns the first pull may not benefit, every scale-from-zero wake on a fresh node is a first pull, Docker Hub rate-limits anonymous pulls per IP, and the bytes are off-Google egress. Fast-starting G2 nodes are GA (2025-11-24) on GKE 1.31+ and are disabled on Spot. Reported end-to-end cold starts for a vLLM L4 Pod range from 3 to 12 minutes; none has been measured by this project.
- vLLM v0.28.0 (2026-08-26): the OpenAI-compatible image is 9.0–10.2 GB compressed, runs as root by default. Read from the project's `main` branch, not the v0.28.0 tag, and so confirmed on the pinned digest before anything relies on them: the HTTP listener starts only after the model is loaded (so `/health` 200 means loaded); `--api-key`/`VLLM_API_KEY`, `--served-model-name`, `--max-model-len`; Prometheus metrics named `vllm:time_to_first_token_seconds`, `vllm:num_requests_running`, `vllm:num_requests_waiting`, `vllm:kv_cache_usage_perc`; `HF_HUB_OFFLINE=1`. Unsourced, and rendered only once `vllm serve --help` on the pinned digest shows them: `--ssl-certfile`/`--ssl-keyfile`, `VLLM_NO_USAGE_STATS`, `DO_NOT_TRACK`. Request logging is left at its default (off) rather than rendering `--disable-log-requests`, which upstream deprecated in favour of `--enable-log-requests` during 2025 and which the pinned version may reject. Prefer the `-cu129` variant on Autopilot's default R535 driver, or the CUDA-13 image with `gke-gpu-driver-version: latest` *[to confirm live: both]*. A 14B model in bf16 (~29.5 GB) does not fit an L4's 24 GB; FP8 (~15.3 GB) fits with a 16–32k context; AWQ 4-bit (~10 GB) fits with ample KV budget at a measured cost of one to two benchmark points.

## Decision

**1. AllThing owns the semantics of asking — who may answer, where the content may be, what it cost — and nothing about the machines that answer (Planck, Kubernetes), the bytes that leave (FatLine), or the money that stops them (TechnoCore).** It is a router with a policy and a lifecycle, not a provider shim. The name stays: the Hyperion AllThing is the forum where every voice is heard and a decision is reached, which describes this better than it described the stub. Sub-packages are plain (`backend`, `policy`, `router`, `runtime`, `gateway`, `catalog`, `deploy`); no new Hyperion names.

**2. An application states one thing about a request: whether its content may leave the instance.** `sdk/go` gains `type Privacy string` with `Private = "private"` (the zero value `""` is read as `Private` everywhere, and the client always sends the word explicitly) and `ExternalAllowed = "external"` — the repository's own word for outside the boundary. `ChatRequest.Model` is removed: it is referenced nowhere, it contradicts "the application never names a provider", and it is the field a fallback chain would key on. `ChatResponse.Served` reports where the answer actually came from. There is no third class; "preferred" is a routing policy the operator owns (decision 5).

**3. The application contract is frozen from 6.0, before any application exists** — the ADR 0008 decision 7 discipline. Frozen: `AIAPI`'s two methods (`Chat`, `ChatStream`); the `Privacy` words; four sentinels — `ErrAIStarting` (wait and retry; woken by this very request), `ErrAIHeld` (the cost limit or an operator hold; do not retry; `AIStatusOf` says which), `ErrAIRefused` (no backend is permitted for this class on this instance; never returned as a fallback), `ErrAIUnavailable` (the total-mapping catch-all) — with `ErrTooLarge` and `ErrPermission` reused; the wire codes `starting | held | refused | too-large | permission` in a new `sdk/go/aiwire.go` (never `wire.go`, which `datasphere/keyholder/wire_test.go` mirrors), pinned by a two-way mirror test in `allthing/gateway` whose regex admits the `AICode` prefix; `X-Farcast-Code` authoritative over HTTP status; a stream that ends without a `done` event is `ErrAIUnavailable`, never a shorter answer. Not frozen: `ChatRequest` and `AIStatus` are structs so fields can be added. Optional capabilities (`AIStatusAPI`, a stream that reports where it was served, embeddings later) arrive as separate interfaces discovered by type assertion, so a two-method application fake keeps compiling.

**4. The effective decision is the intersection, and every absence is a no.** Content leaves only if the application said `ExternalAllowed`, the application's manifest declared `ai.external` with a `reason` the operator reviewed at `farcast run` (the operator's own sessions are exempt from the manifest, not from the policy), the operator enabled a provider on the instance, and either no private runtime exists or the operator set `--fallback when-private-unavailable`. An absent header is private; a word other than the literal permissive one is refused as `bad-request`, never widened; an instance with no `--external` argument has no external backend in memory.

**5. "Private never falls back" is true by construction, in seven layers, each sufficient alone and each with a named test.** (L1) the SDK's zero value and explicit header; (L2) the gateway's normalisation and refusal of unknown words; (L3) `policy.Candidates` is a total pure function that never yields an external backend for `Private`, and the router partitions backends at construction, refuses a backend in the wrong slot, and serves the private path through a distinct function whose imports a test parses; (L4) an external adapter is constructed only when `--external <provider>` **and** its key environment variable are both present, and no Secret is rendered unless a provider is enabled; (L5) provider hosts live only in FatLine's `system` tenant, which is empty unless `farcast ai external enable` rendered `--system-allow`; (L6) NetworkPolicies — the first in `farcast-system` — give the gateway egress to kube-dns, FatLine `:3129`, the inference Pod and the API server only, give the inference Pod **no egress rule at all**, and admit FatLine's `:3129` only from AllThing's Pods; (L7) every decision emits `event.Event{Proto: "ai"}` and Shrike correlates each `forwarded_external` with FatLine's own CONNECT `Allow` on `:3129`, mapping a forward on an instance with no provider enabled to **critical**. Under `FallbackWhenPrivateUnavailable` an `ExternalAllowed` request that finds the private runtime cold goes external only because the operator said so; a `Private` one returns `ErrAIStarting`.

**6. Operating modes are derived, never declared.** `farcast ai status` prints `absent`, `private`, `external-only` (with the warning that every `Private` request is refused) or `private + external by policy` from facts. "External disabled" is the absence of four independently verifiable things: no `--external` argument on the gateway, no `allthing-external` Secret, no provider host in FatLine's `--system-allow`, and `external_backends: []` in the gateway's state. Any one alone makes the guarantee hold.

**7. Until 4.4's per-app leaves, an application's identity on AllThing's data mux is the declared `X-Farcast-App` header — attribution, not authentication, stated plainly (the keyholder's `X-Farcast-Scope` position).** A declared name may carry a manifest-declared external permission because the harm a spoofed name can do is bounded: an application claiming another's name can send *its own* content to a provider the operator already enabled and reviewed a reason for; it cannot make content leave an instance where no provider is enabled, and it cannot reach a provider host itself, because `:3129` is in no application's NetworkPolicy. At 4.4 the data mux gains `RequireAndVerifyClientCert` and the name must equal the leaf's `farcast://<instance>/app/<name>` SAN. The stricter ordering — applications stay private until 4.4 — is a defensible product stance and is recorded as the alternative.

**8. The private backend's contract is an OpenAI-compatible HTTP server on `:8000` with `GET /health` and `POST /v1/chat/completions`, started by one container image, reading weights from a directory, needing one accelerator of a named class.** Nothing above `allthing/deploy` knows what a GPU, a node, a G2 shape or vLLM is; the adapter is `openaicompat`, not `vllm`. Cloud- and vendor-specific facts live in exactly two places: the placement block of the inference template, filled from Planck, and the accelerator row of the rate card.

**9. Planck contributes cloud facts about accelerators through an optional capability and still has no runtime.** `planck.AcceleratorProvider` (beside `RegistryProvider`; discovered by type assertion; `ErrAcceleratorUnsupported` degrades) answers with `AcceleratorClass{Name, MemoryGiB, Selector, Resource, HourlyUSD, AsOf}`; the GKE realisation is a static table — no API call, no new module, no new IAM role. A quota read over the vendored auth transport (needing `compute.googleapis.com` and `roles/compute.viewer`) is deferred to the first runbook finding of a Pod unschedulable for quota; the Pod's own scheduling condition is the honest capacity signal and costs nothing. `allthing/deploy` renders AllThing's workloads, per the module convention; `planck/translate` renders operator applications and refuses `farcast-system`.

**10. The inference workload is a Deployment `allthing-inference` in `farcast-system`, rendered at `replicas: 0`, `strategy: Recreate`, labelled `farcast.sofmon.com/tier: elective` and `farcast.sofmon.com/accelerator: <class>` on workload and Pod template, with the application-side container posture as the documented exception.** vLLM is third-party code that runs as root; it falls on the application side of FarCast's line exactly as Kaniko does in ADR 0010: root accepted and documented; `readOnlyRootFilesystem: true` with named `emptyDir`s at `/tmp`, the compile cache and `/dev/shm` (`medium: Memory`, 2 GiB), relaxed only on runbook evidence, recorded; `allowPrivilegeEscalation: false`; all capabilities dropped; `RuntimeDefault` seccomp; no ServiceAccount token; no host namespaces; the GPU through the device plugin's extended resource, never a device mount; `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `VLLM_NO_USAGE_STATS=1`, `DO_NOT_TRACK=1` (the last two are belt, unverified against the pinned tag; the empty egress list is the control); request logging at its default-off, never `--disable-log-requests`, which upstream deprecated; `--trust-remote-code` never rendered (a test greps the arguments). The compensating control is decision 5's empty egress list: a compromised inference container is a container that can talk to exactly one peer. The hop from the gateway is TLS with a leaf `<instance>.allthing-inference.farcast` plus a bearer key *[to confirm live: `--ssl-*` and `--api-key` on the pinned version]*; if the pinned version cannot, the cleartext hop is stated and the leaf scheduled.

**11. Model weights rest on a PersistentVolumeClaim `allthing-models`, filled by a Job `allthing-fetch` that runs FarCast's own binary and verified by FarCast's own binary before every start.** The catalog (`allthing/catalog`) is reviewed constants — name, one source host, every file's path, size and SHA-256 (the hub's tree API publishes both), quantisation, context, `MinMemoryGiB`, `StartDeadline`, runtime arguments, licence, reviewer and date — admitting `.safetensors`, `.json` and tokenizer files only; `.bin`, `.pt` and `.pkl` are refused by constant and by the fetch code, because a pickle is remote code execution dressed as a model. The Job streams each file through FatLine `:3129` under a `--system-allow` for the catalog's source hosts that `farcast ai model fetch` renders before the Job and removes after it — removal keyed on the Job's completion document, not on the CLI surviving the fetch, and `farcast ai status` names any `system` allowance that is not an enabled provider's host as stale; because the allowlist is exact-host, an entry names every host a download touches (the hub and the CDN hosts its redirects land on), and the fetch refuses a redirect to a host outside the entry rather than following it; verifies as it streams; renames on success; deletes on mismatch. An init container `allthing verify` re-hashes every file before vLLM sees a byte, because the disk is provider-writable and a marker file is not a verification. Hubs do not sign; the reviewed hash is the claim. An update is a new catalog entry, a fetch into a sibling directory and `farcast ai private enable --model <new>` with `Generation+1`; rollback is the previous entry. `farcast ai private enable` refuses a model whose `MinMemoryGiB` exceeds the class's memory before any Pod bills.

**12. The inference image is a digest-pinned upstream reference recorded as a reviewed constant with its maintenance status.** Stated plainly: the kubelet's pull is node-level egress FatLine does not see, and the pin makes the third party untrusted *transport*, not an audited *author* — the image is code that runs as root next to prompts, confined only by its NetworkPolicy. ADR 0007 refused a Docker Hub source in the runtime path for application images because it reintroduces a third party there; this decision argues that exception for the inference image alone — the pin fixes the bytes, the NetworkPolicy fixes what they can reach, and streaming from Docker Hub is expected but unmeasured against a same-region mirror (a 6.2 runbook measurement, not a fact). The mirror into `<prefix>/system/vllm` becomes mandatory when private nodes land (ADR 0004 decision 6); whether it arrives through an Artifact Registry remote repository via `RegistryProvider` (zero new OCI code) or a streaming CLI client with an argued Docker Hub realm exception is Open question 5.

**13. The gateway scales `allthing-inference` between 0 and 1 itself.** `allthing serve` (one replica, `strategy: Recreate`, tier `system`, the keyholder's three-mux shape on `:8443` data / `:8444` status / `:9443` control) holds a ServiceAccount token — the kernel precedent for "the process whose job is the API server holds a token" — and a namespace Role rendered by `allthing/deploy`, never by editing `technocore/deploy`: `deployments [get]` and `deployments/scale [patch]` pinned by `resourceNames: [allthing-inference]`; `pods [list]` (cannot be name-pinned; to explain Pending); `configmaps [get]` pinned to `technocore-status` and `allthing-policy`; and, from 6.4, `configmaps [get, update, patch]` pinned to `allthing-usage`, which `farcast ai deploy` **pre-creates** so the gateway never holds a namespace-wide `create` (a compromised gateway with `create` could author `technocore-confirmed` on an instance whose operator never ran `farcast kernel confirm`). `technocore/kube` gains `GetDeployment`; the comments that say the kernel's ClusterRole grants "exactly what `technocore/kube` calls" are reworded to "exactly what the kernel calls" in the same commit. The controller clamps replicas to `{0, 1}` in code, because RBAC cannot bound a count. A deploy test enumerates the gateway's verbs and fails on `watch`, `delete`, `create`, `escalate`, `bind`, `impersonate` or any unpinned scale verb. The plain-HTTP status mux answers `/v1/state` with exactly what the SDK's `AIStatus` carries — phase, reason, since, generation, whether private is configured, whether external is permitted — and never a model, an accelerator, a provider or the kernel's level, because any Pod with egress to `:8444` can read it; the full document is on the mTLS control mux. The copied import-graph test forbids `golang.org/x/net/trace` beside `pprof` and `expvar` (it registers `/debug/*` on the default mux at init and already sits in the keyholder's graph), and a second test asserts every `http.Server` carries its own non-nil `Handler` — the property that actually keeps `/debug/*` off the keyholder today, and which no test there pins. The gateway logs JSON `slog` records exactly as the keyholder does; convergence on the SDK's record shape is a repository-wide change, not this one.

**14. TechnoCore publishes a status document, records what it stopped, and stops `elective` first.** A named ConfigMap `farcast-system/technocore-status` (`status.json`: version, `at`, `level`, `enforcing`, `limit_usd`, `accrued_usd`, `rate_hourly_usd`, `overhead_hourly_usd`, `period_end`, `projected_over`, `at_floor`, `stopped[]`) is written every tick by `technocore/kernel/status.go` with the `technocore-confirmed` discipline: the kernel's Role gains `get/update/patch` pinned to the name (`create` is already namespace-scoped; the ledger-role test counts 3 → 4 rules); AllThing has `get` only; a failed write is logged and never fails the tick. `stopped` is the marker the kernel never had: `ShutdownResult.Stopped` kept as reconciler state, cleared when the level falls below `reached` and on period roll, **persisted as an additive `omitempty` field on `kernel.Checkpoint` without a version bump** (never on `cost.Snapshot`, whose field set a test pins and which cannot import `tier`), and saved immediately after any shutdown that stopped something, so a restart inside the five-minute checkpoint cadence does not forget. `overhead_hourly_usd` moves the $37 cluster and $18 carrier constants from the CLI's `floor.go` into `technocore/pricing`, correcting the contradiction between ADR 0009 decision 4 and the code, so headroom stops being optimistic by ~$55/month. `technocore/tier` gains `Elective`: `Of()` learns the label (the load-bearing edit — without it the label classifies as `Unknown` and is protected), `Stoppable()` is true, `Valid()` is unchanged so a manifest may not declare it. `Report.Stoppable()` sorts on `(Rank asc, HourlyUSD desc, Name asc)` — one line in `reconcile.go` plus its test — so "elective is stopped before any application" is enforced, not assumed; today `Rank()` is unused by the kernel. ADR 0009 decisions 2, 3 and 6 are amended by this decision: the kernel now writes two ConfigMaps, both passing the cloud-resident-state test (the limit is already in the Deployment's arguments; every other number is provider-computed), and the tier vocabulary has four values.

**15. The wake rule: a scaler that cannot see the meter does not spend.** `Wake` refuses — phase `cost-stopped`, reason named — unless `technocore-status` is present, fresh (`at` within four kernel ticks), `level` is below the ceiling (default `90%`, operator-settable), and `allthing-inference` is not in `stopped`. Absent, stale or unreadable reads as `reached`; `enforcing: false` is the kernel's choice and the level is honoured regardless. `farcast ai private enable` refuses an instance without `meta.Kernel.Deployed` or whose kernel does not meter `farcast-system`. At `reached` the controller sleeps pre-emptively and refuses external too ("nothing new is spent" is what the limit means for tokens). The kernel keeps its backstop: if a bug wakes the runtime while `reached`, the kernel stops it within a tick and records it, after which the controller sees the marker — flapping is bounded to one, not infinite. Nothing acts on `projected_over` (ADR 0009 decision 9); the 90 % ceiling is AllThing's own elective choice about *new* spend.

**16. Cold start is a first-class application state, fail-fast.** A `Private` request that finds the runtime idle *is* the wake signal and is answered in the same round trip with `starting` and `Retry-After`; the SDK maps it to `ErrAIStarting`, distinct from `ErrAIHeld`, `ErrAIUnavailable` and `ErrNotImplemented`. The gateway's data Service is readiness-gated on the gateway (ready as soon as it can classify and refuse honestly), so a cold runtime never yields a dial failure; `allthing-status` publishes not-ready addresses. The SDK consults the status endpoint only to explain an already-failed call, never to retry or downgrade; an unknown phase reads as not-ready. Phases: `absent | unfetched | fetching | idle | starting | ready | draining | failed | cost-stopped | operator-hold`; `failed` after `StartDeadline`, after two crash loops in an hour, or on a verify failure — scaled to zero and held until `farcast ai private retry`, because a crash-looping GPU Pod is the most expensive way to serve nothing; `operator-hold` is not durable across a gateway restart and `release` lands on `idle`, never `ready` (the keyholder rules). Idle-down after `IdleTimeout` (default 10 minutes) with vLLM's own running-requests gauge as the second signal. An `X-Farcast-Wait` derived from the caller's context deadline is an additive header for a later phase.

**17. Accelerator Pods are metered by the node shape the cloud will bill, walked from a dated per-class ladder, and the enable gate quotes what the limit affords.** `technocore/pricing` gains a shape ladder per class (`"nvidia-l4"`: g2-standard-4/8/12/16/32 for one GPU, -24/-48/-96 for two, four and eight, each with vCPU, GiB, on-demand and Spot rates, `Region`, `AsOf`), and `AcceleratedPodHourlyUSD(class, count, cpuMilli, memMiB)` returns the smallest shape that fits the count, the CPU and the memory — never a flat number, because Autopilot's rule is "the machine type that most closely fits" and Google's own example bills a Pod asking for 11 vCPU/40 GB as a g2-standard-12. `kube.ResourceList` gains `Extended map[string]string` through a custom `UnmarshalJSON` capturing any resource key containing `/` — cloud-neutral, read from both requests and limits — and `Pod.Requests()` returns a struct; `kube.PodSpec` decodes `nodeSelector`, and the class is read from `cloud.google.com/gke-accelerator`, which is what the cloud bills on; the `farcast.sofmon.com/accelerator` label is the declaration and must agree, otherwise the Pod is priced as an unknown class. An unknown class, or a count, CPU or memory beyond the ladder, prices at the most expensive known shape and is counted in the report (never flatters, keeps metering — failing the tick would stop accruing everything, which is the flattering direction). The $0.81/h figure holds only while the inference Pod's requests fit g2-standard-4; the runbook reads the node's `node.kubernetes.io/instance-type` label after the first schedule. `farcast ai private enable` is a new gate shape, quoting the per-hour figure, the per-wake minimum, the never-idle ceiling and the GPU-hours the limit affords after the floor, refusing below floor + gateway unless `--yes`; the render test asserts the label equals the selector and the count is one, and `costgate_test` pins the figure to the class parsed back out of the rendered manifest. The node's billing tail after scale-to-zero is measured in the runbook and, if material, becomes a tail constant; until then it is a named line under "what the meter cannot see".

**18. External token spend enters the one limit in two steps and is never a second budget.** From 6.3 the gateway prices tokens from a dated per-provider card and reports them under "external tokens (estimated; not seen by the meter)"; from 6.4 it publishes `allthing-usage` every five minutes and the kernel accrues it as `expected` through `Ledger.AccrueAbsolute` (a missing document is a named state, never zero; the guard can only tighten). Cost-aware routing, when it exists, is an ordering rule over already-permitted backends in `policy.Policy`, fed by the kernel's level — never in the SDK, never in the kernel, never across a privacy class.

**19. Configuration is CLI verbs, a metadata block and rendered arguments and Secrets, exactly as for every other system component.** A `farcast ai` group (`deploy`, `status`, `private enable|disable|retry|warm|hold|release`, `model fetch`, `external enable|disable`, `remove`) and a top-level `farcast chat` replacing the stub; `meta.AI` holding nothing secret. FatLine's rendering learns to read metadata: `renderWorkload` takes `meta.AI` and renders the `allthing` route and every `--system-allow` from it, `connect` and `redeploy` both render from it, and `ai status` names the drift when a FatLine rendered without them is running — a pre-AI CLI's `redeploy` drops the route and the allowances, which fails closed and must be said, not discovered. `farcast ai deploy` inherits the FatLine deployer's tag rule: the image tag is the CLI's version, so a preflight hit redeploys whatever `system/allthing:<version>` already holds and a gateway change ships only with `--source` or a version bump; `allthing/deploy` validates the `@sha256` pin itself, as `technocore/deploy` does and `fatline/deploy` does not. `cluster.Client` gains `Delete(ctx, ns, kind, name)` (`--ignore-not-found --wait --timeout`), on the CLI's `clusterApplier` seam and its test fake too; `farcast ai remove` waits for the inference and fetch Pods to leave before deleting the PVC, because the `pvc-protection` finalizer otherwise holds the billing disk through vLLM's termination grace. `farcast release` calls `ai remove` **before** it writes `InstanceDeleting` (a status `redeploy` refuses, and `ai remove` re-renders FatLine); if the API server is unreachable, `release` proceeds to `DeleteCluster`, prints the PVC's disk as a possible orphan and records it, and the runbook establishes live whether GKE deletes a dynamically provisioned disk with its cluster. `farcast chat` is its own client in the keyholder client's shape, not its code: no 30 s request timeout, no 1 MiB cap, a 120 s inter-chunk idle limit mirroring the SDK's because the HTTP/2 transport sends no liveness pings, and it never half-closes the relayed stream after writing the request — FatLine turns a half-close into a FIN toward the gateway and Go's HTTP/1.1 server cancels the handler on it; a probe against the real relay showed zero deltas. A stream severed by a FatLine rollout or eviction (5 s drain) is `ErrAIUnavailable`, never a shorter answer, and the `state` heartbeat interval is pinned in the wire spec. The deployed FatLine sets no `AllowClientIdentity`, so any instance-CA leaf, keeper devices included, can open the `allthing` route: the control mux's URI-SAN check is the only thing keeping them out, and a test proves a keeper leaf is refused. The manifest changes nothing in the first milestone and gains one additive, reviewed key with the external phase: `ai.external.reason`, a security contract like `external:` with its `reason`, rendered by `farcast run` into an operator-written, gateway-read `allthing-policy` ConfigMap. No instance-level configuration file; no model, accelerator or resource hint in a manifest.

**20. FatLine's Service publishes its egress ports on a ClusterIP, never on the carrier.** The rendered `fatline` Service today carries only the tunnel port and is `type: LoadBalancer`; publishing `:3128`/`:3129` on it would expose an unauthenticated CONNECT proxy on the instance's public IP. A second, always-ClusterIP Service `fatline-egress` publishes 3128 and 3129; `planck/translate` points `FARCAST_FATLINE_PROXY` at it, closing the pre-existing defect that the translator's URL names a port no Service publishes; `TestTheCarrierServicePublishesOnlyTheTunnelPort` and `TestTheEgressServiceIsClusterIP` pin the shape, and ADR 0005 gains a dated note that the egress listeners are cluster-internal, unauthenticated by design, and never ride the carrier. FatLine's first NetworkPolicy ships in the same commit as the `:3129` listener and states its three ingress rules explicitly — `:8443` from any source, `:3128` from application namespaces, `:3129` only from AllThing's Pods in `farcast-system` (a `namespaceSelector` with the `podSelector`, because an application may name itself `allthing` in its own namespace); the runbook confirms from outside the cluster that a CONNECT to `:3129` on the carrier's address is refused at the connection level. `SlogSink` learns to print the event's `Tenant`, without which the runbook's "zero `Allow` for tenant `system`" is unobservable. In the same change the translator's storage status URL becomes `http://` (the listener is plain HTTP; the rendered `https://` would report a sealed fleet as unavailable rather than sealed).

**21. AllThing output never authorises an action.** Future system callers (TechnoCore, Shrike; PLAN 6.4) get text they display or rank, never execute; the gateway adds no system prompt carrying cluster facts; no tool-calling in the first implementation. Log-borne prompt injection reaches command execution in most open 12–14B models tested (LogJack, 2026), and a model that reasons over logs is reading untrusted content by definition.

**22. The first milestone is a private answer with the guarantee provable from outside, reached through a no-GPU phase first.** 6.0 fixes the contract and corrects the documents; 6.1 ships the gateway that refuses and the kernel's cost half over fakes (tier, status document, GPU sight, the controller's wake-refusal tests) at ~$3.70/month, so the flapping conflict is closed before the first GPU dollar; 6.2 ships FatLine's `:3129`, the catalog, the fetch Job, the PVC, the runtime and scale-to-zero, walked by a runbook whose criterion that matters most is FatLine's own event log showing **zero `Allow` for tenant `system`** outside the fetch window and a `kubectl exec` from the inference Pod that cannot resolve a name. External-first is rejected (it ships the leak path before the constraint); an always-on GPU phase is rejected (~$589/month against a $100 limit, stopped by the kernel within days, proving nothing about the mechanism that makes private inference fit).

## Consequences

**What this buys, stated without softening.** A `Private` request cannot reach a provider by any path short of a compromised gateway binary, and seven independent layers plus a live criterion say so. The GPU exists only while it is being used and never against the kernel. Applications inherit a contract fixed before any of them exist. The instance, not the laptop, fetches and verifies what it runs.

**What it costs, and what the cloud still sees.** Private inference is *protected by Google not looking* — ADR 0008's phrasing applies unchanged: prompts, completions and the KV cache exist in plaintext in the inference container's memory, in GPU memory and in the gateway's memory, on the provider's hardware; a node memory snapshot, a live migration or a hypervisor-level read exposes them, and this is not defended. Weights rest on a provider-managed disk the provider can snapshot; they are public, so what the cloud learns is *which model*. Every wake is a node-provisioning event with a timestamp in the provider's logs and bill: a scale event means "someone asked something private". Request timing and byte sizes cross the VPC; token counts are approximately derivable from streaming cadence. The status, policy and usage documents are cloud-resident and carry app names and counts, never prompts. Nodes have external IPs (private nodes deferred); the kubelet pulls the inference image from a third-party registry; GPU utilisation is visible to the provider through its own metrics whether or not FarCast reads them. Hidden from every third party other than the cloud provider: everything. Hidden from the cloud provider: nothing that is in memory — the cloud is blind to content on the wire because of TLS, not blind. With a provider enabled, an `ExternalAllowed` request that is served externally is content leaving sovereignty entirely, under the provider's terms; FatLine and Shrike see host, port, SNI and bytes; the application is told.

**Money.** Under a $100 limit private inference is about 28 GPU-hours a month; under $50 it is nothing, and the gate says so rather than pretending. Each wake costs a modelled $0.20–0.30 of billed node time *[to confirm live]*. Every dollar figure here is modelled from the rate card and unreconciled against a bill, and the shape Autopilot actually picks is the first thing the runbook reads. The accelerator rate is a second unverified model on top of the first; criterion 12 of the 4.1 runbook now covers two lines. The PVC (cents) and the registry (once anything is mirrored) become computed lines, not the "~$0" comment.

**Availability and placement.** A zonal PersistentVolume pins the inference Pod to one zone of a regional cluster; a stock-out in that zone blocks a wake while other zones may have capacity. Stated as a limitation; the revisit is a runbook finding, the W4 path, or Hyperdisk ML once Autopilot support on the cluster's version is confirmed. Cold starts are minutes; `StartDeadline` and `IdleTimeout` defaults are set from five measured starts, not from this document. The metered namespace set is fixed at `farcast kernel deploy`; a kernel deployed without `farcast-system` neither meters nor stops the runtime, which is why decision 15 refuses to enable without it.

**The inference Pod is the least-hardened Pod in `farcast-system`** — root, a writable cache, a third-party image — and the README says so. Its egress list is empty; that is the control.

**Per-module implications.** *SDK:* `Privacy`, `Served`, `Usage`, roles, four sentinels, `aiwire.go`, a three-outcome accessor on `FARCAST_AI_ENDPOINT` / `FARCAST_AI_STATUS_ENDPOINT` (http) / `FARCAST_AI_CA` / `FARCAST_AI_SERVER_NAME`, `AIStatusOf`; `Model` removed with a changelog note. *TechnoCore:* `tier.Elective` (with `Of()`), the sort, `technocore-status`, the checkpoint field, the accelerator shape ladder, `ResourceList.Extended`, `PodSpec.NodeSelector`, `GetDeployment`, README rows. *FatLine:* `allowlist.SystemTenant` with a per-tenant constructor (`build` is unexported today), a `Tenant` on `proxy.Options`, a second proxy and listener, `--system-egress-listen`/`--system-allow`, `fatline-egress`, its first NetworkPolicy, `AllThingServerName`/`InferenceServerName`/`Issue*` plus `IssueSystemClient` for the later `/system/<name>` identities, the `allthing` stream route; events carry `Tenant` and `SlogSink` prints it; an e2e test in the keyholder-client shape that asserts deltas arrive before the handler returns and that a half-closed variant fails loudly. *Shrike:* the `ai` reason map and the forward/CONNECT correlation. *Planck:* `AcceleratorProvider`; the translator's `FARCAST_AI_*` block, the egress rule, the `fatline-egress` name and the status-scheme fix. *FarSight:* the `ai` group, `chat`, `meta.AI`, `FatLineRoutes`, `renderWorkload` reading `meta.AI`, drift named by `ai status`, the while-active gate, `cluster.Client.Delete` on the `clusterApplier` seam and its fake, release ordering. *Manifest:* a Reserved-list entry now; `ai.external.reason` (rules 31–34) with 6.3.

**Sentences this ADR corrects, in place:** `README.md:86,93,163,238,250` and the status table; `AGENTS.md:11,50`; `docs/hyperion-reference.md:57`; `allthing/README.md` (replaced by the specification); `sdk/go/ai.go:5-8`, `sdk/go/farcast.go:19-22`, `sdk/go/README.md:89,95,379` and its roadmap; `PLAN.md:276-310, 374-375` and the missing 4.1/4.2 Status lines; `farsight/cli/README.md:79,914`; `shrike/README.md:210`; `technocore/README.md:16-18`; `manifest/README.md` Reserved list; a dated note on `docs/adr/0002:27` ("still Go, still stdlib HTTP+SSE, no provider SDKs; the first backend is an in-instance OpenAI-compatible runtime"); ADR 0010's status to Accepted, its decision 5 gaining "first implemented here".

### Phasing

- **6.0** — Contract and corrections: `allthing/README.md` as the specification; the SDK changes; `allthing/gateway/wire.go` and its mirror test; `allthing/docs/wire.md` with golden fixtures for the Node/Python SDKs; the translator's `HasAI` block and both status-scheme fixes; the manifest Reserved entry; every sentence above. Nothing deployed.
- **6.1** — The gateway that refuses, and the kernel's cost half: `backend`, `policy`, `router`, `runtime` over a fake `Cluster`, `gateway`, `allthing serve`, `allthing/deploy` (gateway objects and its NetworkPolicy), identity leaves, the stream route, `farcast ai deploy|status|hold|release`, `farcast chat` replacing the stub; `tier.Elective`, `technocore-status`, `ResourceList.Extended`, the accelerator table, the sort. Runbook 6.1: `farcast chat` answers "no backend is permitted — run `farcast ai private enable`"; the walk costs under $1.
- **6.2** — Private inference with scale-to-zero, three standalone commits: (a) FatLine's `:3129`, `fatline-egress`, its NetworkPolicy; (b) the catalog, `allthing fetch`/`verify`, PVC, Job, the inference Deployment and its NetworkPolicy, `planck.AcceleratorProvider`, the controller on the real client, `farcast ai private enable|disable|retry|warm`, `model fetch`, `remove`; (c) the runbook with five measured cold starts and the node tail. **The first milestone ends here.**
- **6.3** — Applications and external providers by declared policy: `openaicompat` for OpenAI and an `anthropic` adapter (stdlib HTTP+SSE, no SDKs; 31 modules before and after, measured); Secret via stdin; `farcast ai external enable|disable`; `--fallback`; manifest rules 31–34 and `allthing-policy`; Shrike's map; token spend reported. The manifest path waits for 4.3; the operator's `farcast chat --external` does not.
- **6.4** — Cost participation and hardening: `allthing-usage` and `AccrueAbsolute`; `farcast costs` lines; the tail constant if material; the wait header; runtime TLS if 6.2 shipped cleartext; Shrike sidecar templating when Planck 4.2's two-container Pod lands; per-app rate limits.
- **6.5** — System callers under decision 21 (the old 6.4). **8.3** — a Gemini dialect and a second accelerator class or cloud realisation of `AcceleratorProvider`. Deferred with named triggers: the image mirror and the OCI weights path (private nodes; a hub rewriting an entry); Planck's quota read (first quota finding); secondary boot disks (a measured pull dominating cold start); Spot for the elective runtime; embeddings, vision, reranking; a chat endpoint on a FarSight server that does not yet exist.

### Revisit triggers

1. **Private nodes land** (ADR 0004 decision 6) — the inference image must be mirrored into the instance registry, and the OCI-artifact weights path becomes the better answer.
2. **A cold start measured above ten minutes, or a zonal stock-out finding** — reconsider the PVC (Hyperdisk ML, a regional disk, or W4) and secondary-boot-disk preloading.
3. **The first `confirmed` window on an instance that ran the GPU** — the accelerator rate meets an invoice; if the drift exceeds the clamp, the node tail or the shape choice is wrong in kind.
4. **Per-app leaves (4.4)** — the data mux gains client-certificate verification and the FatLine `system` listener may become the mTLS listener of F2.
5. **A first application that cannot tolerate a minutes-long cold start** — a warm-keep window changes the cost model and is its own decision.
6. **Spot capacity for the elective runtime** — ~40 % cheaper today, another cold start on every preemption, fast-starting nodes disabled; reconsider once cold starts are measured.
7. **A second cloud** — a new `AcceleratorProvider` realisation and a rate-card row; if that cloud bills accelerators by request rather than by shape, decision 17's mechanism, not its constant, is what changes.
